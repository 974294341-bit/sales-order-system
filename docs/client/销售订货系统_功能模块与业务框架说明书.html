一、文档说明

本文档面向客户，系统阐述「销售订货管理系统」的功能模块、业务框架与关键规则。文档内容为产品交付与方案说明材料，用于对外演示、评审与交付，不涉及任何内部考核或评分口径。

系统从接单、评审、变更、排产、入库发货到交付率统计，覆盖销售订货的完整业务闭环；按岗位分工提供清晰的协作工作台，并配套 PC 端与手机端一致的审批体验。各章节的说明均对应系统已实现的真实能力。

二、系统概述

销售订货管理系统是一套面向制造与贸易企业的销售订货全流程数字化协同平台。系统以「岗位分工、流程可控、规则前置」为设计原则，帮助企业在订单处理过程中明确权责、缩短评审周期、降低交付风险。

核心能力包括：

  • 订单全生命周期管理：从录入、评审、变更到发货与交付率统计；
  • 按岗位分工的协作工作台：不同岗位仅看到并执行其职责范围内的模块与待办；
  • 多端一致的审批体验：PC 工作台与手机端共用同一套审批任务与流程进度；
  • 业务规则引擎：库存优先、财务前置、并行会签、急插单控制、交付率统计、超时升级；
  • 集中式状态机与可视化流程进度：非法状态跳转在边界处直接拦截。

三、优化后的业务框架

系统在流程设计上明确了「库存优先短路、财务前置、并行会签、预测免签字但免校验豁免」等原则，并按岗位划分权责，使订单处理既高效又可控。

3.1 主流程（十一步）

  • 1. 订单来源：客户销售合同 / 月度预测计划；
  • 2. 业务助理录入销售订单，系统校验样品鉴定、试产、BOM 与生产周期表；
  • 3. 库存优先短路：库存齐备 → 财务审核后直接生成发货单出库；库存不足 → 进入评审；
  • 4. 财务前置：校验价格、客户信用额度、收款条款，未通过直接退回业务；
  • 5. 区分标准 / 非标订单，自动分派审批人，工程 / 计划 / 采购 / 品质并行会签；
  • 6. 各部门按系统计算的时限完成评审，驳回退回业务修改；
  • 7. 评审通过归档转生产；预测订单由 PMC 统一录入，免签字但基础校验不豁免；
  • 8. 生产完工入库，按最新约定交期开具发货单并出库；
  • 9. 发生变更：提交变更通知单，按类型分派会签，保留版本历史并更新订单；
  • 10. 急插单：提前 7 个工作日 + 产能校验 + 客户同意顺延 + 月度上限，通过后才走完整评审；
  • 11. 每月统计准时交付率；每半年更新生产周期表；联络单闭环归档；超时自动升级。

六、关键业务规则详解

6.1 库存优先短路

接单时系统先判断库存是否齐备。库存齐备的订单跳过完整评审链，经财务审核后直接生成发货单出库；库存不足的订单才进入正式评审流程。该规则避免了「库存充足却仍跑完整评审」的资源浪费。

6.2 财务前置

评审链的第一步是财务前置校验：系统校验价格、客户信用额度与收款条款，校验不通过直接退回业务部修改，避免在信用或价格未确认的情况下继续后续评审。

6.3 并行会签

标准产品由工程部（BOM 复核）与计划部（交期评审）并行处理；非标产品在 BOM 初稿后，由工程、计划、采购、品质四部门并行会签，全部通过才推进下一阶段，显著缩短评审周期。

6.4 订单变更处理

变更按类型分派评审人：交期变更由计划部处理，数量变更由计划部 + 财务部处理，产品规格 / BOM 变更由工程 + 计划 + 采购 + 财务处理。系统保留变更前后的版本快照，数量 / 规格变更需经财务金额确认。

6.5 急插单控制

急插单需满足：提前 7 个工作日、计划部产能校验通过、业务部取得客户同意顺延确认，且当月急插单不超过月度上限（默认 5 单）。两项前置并行校验全部通过后才可提交评审；驳回即取消插单，且不改变原订单交期。

6.6 准时交付率

以变更确认后的「最新约定交期」为考核基准（而非订单原始交期），正常订单、急插单、预测订单分组统计，每月出具准时交付率报告并由计划部制定改善措施。

6.7 超时与升级（SLA）

系统对所有审批节点进行 SLA 超时扫描，逾期自动升级给部门主管并留痕；工程部 BOM 评审从接收任务当日起计时，最多顺延 3 个工作日，超时自动告警。

6.8 移动端权限边界

手机端仅保留查看单据与流程进度、通过 / 驳回待办、填写评审意见；不允许创建或修改销售订单、发货单、变更单、基础资料，也不允许直接修改订单核心字段，订单内容修改一律走《销售订单变更及通知单》。

八、部署与技术说明

  • 技术栈：Java（基于 JDK 内置 HTTP 服务，零第三方依赖），前端为原生 HTML / CSS / JS，无需构建步骤；
  • 多端一致：PC 工作台与手机端审批共用同一套流程引擎与数据，两端流程进度一致；
  • 权限模型：基于角色的访问控制（RBAC），移动端权限边界明确；
  • 数据安全：采用 JSON 持久化、原子替换写入，并支持数据版本迁移；
  • 演示账号：各岗位提供统一演示口令，登录页可快捷切换岗位体验审批流；
  • 扩展建议：存储与认证层可按需替换为数据库与专业鉴权组件，流程引擎、状态机与业务规则可原样保留。
